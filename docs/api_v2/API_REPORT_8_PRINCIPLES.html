I. Tổng Quan Kiến Trúc Hệ Thống & Yêu Cầu Phi Chức Năng

1. System Design & Tải Trọng (High Concurrency)

  • Mô hình: Monolith NestJS 11 + Mongoose + Qdrant Vector DB + node-llama-cpp (Inference LLM local).
  • Khả năng chịu tải: Đạt chứng nhận chịu tải 400 Concurrent Users (CUs) với thông lượng 250 RPS, P95 latency < 265.54ms qua đường hầm Cloudflare TCP Tunnel (MongoDB localhost:27018).
  • Chiến lược Caching: In-memory Generation-versioned LRUCache + Singleflight triệt tiêu hiện tượng Cache Stampede tại t = 120s.
  • LLM Throttling & Protection: Bounded semaphore queue (LLM_CONCURRENCY=1, LLM_MAX_QUEUE=8). Tự động shed load trả về 429 Too Many Requests khi quá tải.

2. Thiết Kế Cơ Sở Dữ Liệu & Thực Thể (DB Schemas)

  • Định danh khóa chính: Toàn bộ chat_sessions và chat_messages dùng RFC 9562 UUIDv7 (sắp xếp tự nhiên theo thời gian, ngăn chặn enumeration attack).
  • Cơ chế Xóa mềm (Soft-Delete): Lọc bắt buộc deleted_at: null trên 100% truy vấn dữ liệu người dùng.
  • Bảo mật phân quyền (RBAC): Phân tầng user và admin. Cơ chế token_version thu hồi tức thì token khi admin khóa tài khoản hoặc hạ quyền.
  • Audit Trail Bất biến: Collection admin_audit_logs là Append-Only (không có bất kỳ API hay Service method nào được sửa/xóa log).

II. Báo Cáo Thiết Kế API Theo 8 Nguyên Tắc ByteByteGo

1. Domain Model Driven
Ánh xạ thực thể miền, URI phản ánh quan hệ cha-con, Max Depth ≤ 2 		• Thiết kế hướng miền phân cấp rõ ràng:
- Session → Messages: /chat-sessions/{id}/messages
- User → Tokens: /admin/users/{id}/tokens
- User → Sessions: /admin/users/{id}/chat-sessions
• Không vượt quá 2 cấp độ (Max Depth = 2) tránh URL cồng kềnh, dễ vỡ. 		✓ ĐẠT 100%
File: chat-sessions.controller.ts, admin.controller.ts
2. Choose HTTP Methods
Sử dụng đúng ngữ nghĩa: GET, POST, PUT, DELETE, PATCH 		• GET: Truy vấn danh sách và chi tiết.
• POST: Tạo mới token, tài khoản, gửi câu hỏi RAG.
• PUT: Cập nhật toàn phần (đổi password, cập nhật quyền roles).
• PATCH: Cập nhật một phần (đổi tên session, cập nhật profile).
• DELETE: Xóa mềm session, thu hồi refresh token. 		✓ ĐẠT 100%
Phân biệt rạch ròi giữa PUT và PATCH
3. Implement Idempotence Properly
GET/PUT/DELETE tự nhiên idempotent; POST xử lý qua Idempotency-Key 		• DELETE /chat-sessions/{id}: Luôn trả 204 No Content dù gọi lại nhiều lần.
• POST /rag/queries & POST /rag/chat: Hỗ trợ header Idempotency-Key: <UUID> lưu trữ 24 giờ. Khi gọi lặp lại cùng key, server replay câu trả lời cũ kèm header Idempotent-Replayed: true mà không sinh lại LLM lần 2. 		✓ ĐẠT 100%
Test E2E: a repeated chat request replays stored answer
4. Choose HTTP Status Codes
Xóa bỏ "200 OK with Error Body"; Chuẩn hóa RFC 9457 Problem Details 		• 201 Created: Tạo token và tạo tài khoản.
• 204 No Content: Xóa session, đăng xuất, đổi mật khẩu.
• 404 Not Found: Áp dụng cả khi session thuộc user khác (chống quét ID).
• 405 Method Not Allowed: Tự động gắn kèm header Allow: GET, POST....
• 406 Not Acceptable & 415 Unsupported Media Type.
• RFC 9457: Ở v2, 100% lỗi trả về application/problem+json đồng bộ mã status. 		✓ ĐẠT 100%
File: problem-details.ts, http-exception.filter.ts
5. Versioning
Khuyến nghị: Path-based Versioning (/v1, /v2) 		• Áp dụng chuẩn Path Versioning được khuyến nghị trong infographic ByteByteGo:
- /api/v1/*: Giữ nguyên vẹn 100% backward compatibility.
- /api/v2/*: Nâng cấp chuẩn quốc tế RFC 9457.
• Hai phiên bản chạy song song đồng thời trên cùng một engine backend. 		✓ ĐẠT 100%
Config: setGlobalPrefix('api/v1', { exclude: ['api/v2/(.*)'] })
6. Semantic Paths
Dùng danh từ số nhiều, kebab-case, tuyệt đối không dùng động từ 		• Loại bỏ hoàn toàn động từ: /auth/login → /auth/tokens, /auth/logout → /auth/tokens/revoke, /rag/chat → /rag/queries.
• Danh từ số nhiều, kebab-case: /chat-sessions, /papers, /users, /audit-logs.
• Thống nhất 100% tên trường dữ liệu chuẩn snake_case (đặc biệt là is_active). 		✓ ĐẠT 100%
Test E2E: follows design rules: kebab-case nouns, no verbs
7. Batch Processing
Hỗ trợ thao tác đơn lẻ và thao tác hàng loạt qua query ID list 		• Papers:
- Đơn lẻ: GET /api/v2/papers/{paper_id}
- Hàng loạt: GET /api/v2/papers?ids=id1,id2,id3 (giới hạn tối đa 20 IDs).
• Chat Sessions:
- Đơn lẻ: DELETE /api/v2/chat-sessions/{id}
- Hàng loạt: DELETE /api/v2/chat-sessions?ids=id1,id2 (giới hạn tối đa 50 IDs). 		✓ ĐẠT 100%
File: papers.controller.ts, chat-sessions.controller.ts
8. Query Language
Phân trang (Pagination), Sắp xếp (Sorting), Lọc (Filter op:value) 		• Phân trang: Cursor pagination kết hợp limit & cursor. Ép kiểu @Type(() => Number) tránh lỗi 400.
• Sắp xếp (Sort): Cú pháp ?sort=created_at:desc,email:asc.
• Bộ lọc (Filter): Cú pháp field=op:value chính xác như ByteByteGo minh họa: ?created_at=gte:2026-01-01,lt:2026-02-01, ?message_count=gt:2,lte:20. 		✓ ĐẠT 100%
File: src/common/pagination/pagination.ts
