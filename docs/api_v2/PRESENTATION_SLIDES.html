Phần I • Phân Tích Yêu Cầu

Yêu Cầu Chức Năng & Phi Chức Năng (SRS)

Định hình bài toán hệ thống: Hỏi đáp học thuật trích dẫn thời gian thực với độ trễ tối thiểu và tính sẵn sàng cao.

⚡ Yêu Cầu Chức Năng (Functional Requirements)
  • Scientific RAG Pipeline: Nhúng truy vấn (Nomic v1.5) → Duyệt cây tri thức World 3D → Hybrid Search Qdrant → Rerank uy tín tác giả (PageRank Co-authorship) → Qwen2.5-7B sinh câu trả lời.
  • Server-Sent Events (SSE) Streaming: Stream thời gian thực từng token, emit sự kiện chuỗi: phase → route → retrieval → token → done.
  • Quản Lý Phiên & Hội Thoại: Tự động trao đổi lưu trữ phiên chat, phân trang cursor, tìm kiếm regex an toàn, soft-delete.
  • Bảo Mật & Phân Quyền (RBAC): Quản trị viên (Admin) và Người dùng (User). Cấp phát, xoay vòng và thu hồi JWT tokens.
🛡️ Yêu Cầu Phi Chức Năng (Non-Functional Requirements)
  • Khả Năng Chịu Tải: Duy trì ổn định ở 400 Concurrent Users, thông lượng 250 RPS, không sập DRAM hoặc nghẽn Event Loop.
  • Tính Sẵn Sàng (High Availability): MongoDB Replica Set (3-nodes) hỗ trợ ACID Transactions; Health check định kỳ tự động chuyển trạng thái ok / degraded / down.
  • Bảo Mật Cấp Cao: Băm mật khẩu bằng Argon2id (64MB RAM, 4 parallelism), chống Brute-Force, tự khóa Progressive Lockout, Anti-Enumeration 404.
  • Chuẩn Hóa Giao Thức: Song song `/api/v1` và `/api/v2`, lỗi chuẩn RFC 9457 Problem Details.
Phần II • System Design

Kiến Trúc Hệ Thống & Luồng Dữ Liệu RAG

Mô hình phân lớp tách biệt: HTTP Adapter → Frozen Domain Core → Vector DB & Inference Engines.

[ Client / Frontend 3D ]  ⟺  [ Reverse Proxy / Cloudflare TCP Tunnel ]
↓
[ NestJS Monolith (Port 3000): Helmet • RateLimiter • ContentNegotiation • ValidationPipe • HttpExceptionFilter ]
↓
• Auth & Sessions: MongoDB Replica Set (rs0, users, chat_sessions, tokens, audit_logs)
• Retrieval Engine: Nomic Embed v1.5 (768-dim) → Qdrant (scientific_papers_gold)
• Mining Engine: Co-authorship PageRank & FP-Growth (Authority Boosting)
• Inference Engine: node-llama-cpp → GGUF Qwen2.5-7B (Bounded Semaphore Queue)
1. Layer Adapter (API)

Controllers, DTOs, Guards, Interceptors. Tiếp nhận HTTP request, validate, áp dụng HATEOAS và bọc dữ liệu.

2. Layer Domain (Service)

Bất biến (Frozen Core). Nắm giữ toàn bộ nghiệp vụ, quản lý transactions và cơ chế generation-versioned caching.

3. Layer Engines

Vector Store (Qdrant), LLM Inference (node-llama-cpp), Embedding, 3D Tree Router, Graph Data Mining.

Phần III • Hiệu Năng & SRE

Khả Năng Chịu Tải, Mở Rộng & Tính Sẵn Sàng

SRE Benchmark: 400 Concurrent Users (250 RPS) trên đường hầm MongoDB 15-25ms RTT.

P95 Latency SLA
265.54 ms

Vượt tiêu chuẩn SLA yêu cầu (< 500ms) ở tải đỉnh 400 CUs.

Zero DRAM Thrashing
UV_THREADPOOL = 4

Ghim cố định 4 worker thread cho Argon2id tránh nghẽn băng thông RAM.

LLM Semaphore Queue
Concurrency=1, Max=8

Tự động shed-load trả về 429 khi hàng đợi LLM vượt ngưỡng 8 request.

⚡ Bí Quyết Kiến Trúc: 2-Tier Caching & Invalidation Contract
  • Anti-Stampede với Singleflight: Khi Cache Miss ở đỉnh tải t = 120s, chỉ duy nhất 1 request đầu tiên được xuyên xuống MongoDB, các request đến sau cùng đợi trên một Promise.
  • Generation-Versioned LRUCache: Mỗi user có một generation ID. Khi có hành động thêm/xóa/sửa, hệ thống chỉ tăng generation lên 1, lập tức vô hiệu hóa $O(1)$ toàn bộ các trang cache phân trang của user đó mà không cần duyệt quét database.
  • Bắt buộc dùng .lean(): Toàn bộ truy vấn đọc MongoDB dùng .lean() để bỏ qua overhead hydration của Mongoose, giảm 40% memory pressure.
Phần IV • Cơ Sở Dữ Liệu

Thiết Kế Database Schemas & Sơ Đồ Thực Thể

Mô hình dữ liệu MongoDB tối ưu cho High-Concurrency, Trích dẫn Khoa học & Audit Trail.

Sơ Đồ Thực Thể (ERD Relationships)
User (1) ——< (N) RefreshToken (family_id, token_hash)
  ⊤                        
  |——< (N) ChatSession (_id: UUIDv7, title, last_message_at)
  |                    ⊤
  |                    |——< (N) ChatMessage (_id: UUIDv7, role, citations)
  ⊤
AdminAuditLog (Append-Only: actor_id, action, target_id, ip, req_id)
ChatRequest (Idempotency Key Store, 24h TTL)
Các Bất Biến Cốt Lõi Về Dữ Liệu
  • RFC 9562 UUIDv7 Khóa Chính: Session và Message ID chứa sẵn timestamp ở đầu, hỗ trợ sort tự nhiên không cần index riêng trên created_at.
  • Chính Sách Xóa Mềm (Soft-Delete): Không bao giờ xóa cứng dữ liệu người dùng; trường deleted_at làm tombstone bảo toàn tính toàn vẹn.
  • 1-RTT Atomic Token Rotation: Dùng findOneAndUpdate atomic trên refresh token. Nếu phát hiện token đã thu hồi bị dùng lại → lập tức revoke toàn bộ token family (chống đánh cắp phiên).
  • Append-Only Audit Trail: admin_audit_logs không cung cấp hàm update/delete ở bất kỳ tầng nào.
Phần V • RESTful Design (ByteByteGo)

Chuẩn Hóa API Theo 8 Nguyên Tắc (Phần 1)

Hiện thực hóa 4 nguyên tắc đầu tiên từ infographic chuẩn quốc tế của ByteByteGo.

1. Domain Model Driven (Max Depth ≤ 2)

Tài nguyên phản ánh quan hệ miền thực thể, không lồng ghép quá 2 cấp độ:

  • GET /chat-sessions/{id}/messages (Cấp 2)
  • GET /admin/users/{id}/tokens (Cấp 2)
  • Tránh tuyệt đối URL lồng sâu như /users/1/sessions/2/messages/3.
2. Choose HTTP Methods

Tuân thủ nghiêm ngặt ngữ nghĩa HTTP Methods:

  • GET: Đọc dữ liệu (danh sách & chi tiết).
  • POST: Tạo mới token, tạo tài khoản, hỏi đáp RAG.
  • PUT: Cập nhật toàn bộ (đổi mật khẩu, gán quyền roles).
  • PATCH: Cập nhật một phần (đổi tên session, cập nhật profile).
  • DELETE: Xóa mềm session, thu hồi token.
3. Implement Idempotence Properly

Xử lý tính lũy đẳng (Idempotence) an toàn:

  • DELETE: Luôn trả 204 No Content dù gọi lại nhiều lần.
  • POST /rag/queries: Hỗ trợ header Idempotency-Key lưu 24h, replay kết quả cũ kèm Idempotent-Replayed: true.
4. Status Codes & RFC 9457 Problem Details

Xóa bỏ triệt để căn bệnh "200 OK with Error Body":

  • 201 Created cho tạo token; 204 cho xóa / thu hồi.
  • 405 Method Not Allowed kèm header Allow: GET, POST...
  • 415 Unsupported Media Type & 406 Not Acceptable.
  • Lỗi v2 trả về chuẩn application/problem+json theo RFC 9457.
Phần V • RESTful Design (ByteByteGo)

Chuẩn Hóa API Theo 8 Nguyên Tắc (Phần 2)

Hiện thực hóa 4 nguyên tắc tiếp theo: Versioning, Semantic Paths, Batching & Query Language.

5. Versioning (Path Versioning)

Áp dụng chuẩn đề xuất của ByteByteGo (URL Path):

  • /api/v1/*: Giữ nguyên vẹn 100% không làm gãy client/test cũ.
  • /api/v2/*: Bộ API mới chuẩn quốc tế RFC 9457.
  • Chạy song song độc lập trên cùng 1 server instance.
6. Semantic Paths (Danh từ số nhiều)

Loại bỏ 100% động từ trong URL:

  • /auth/login → POST /auth/tokens
  • /auth/token-rotations → POST /auth/tokens/refresh
  • /auth/token-revocations → POST /auth/tokens/revoke
  • /rag/chat → POST /rag/queries & /rag/queries/stream
  • Danh từ số nhiều, kebab-case: /chat-sessions, /papers.
7. Batch Processing

Hỗ trợ thao tác đơn lẻ và hàng loạt:

  • Đơn lẻ: GET /papers/{id}, DELETE /chat-sessions/{id}.
  • Hàng loạt: GET /papers?ids=id1,id2,id3 (tối đa 20 papers).
  • Batch Delete: DELETE /chat-sessions?ids=id1,id2 (tối đa 50 sessions).
8. Query Language (Pagination, Sort, Filter)

Cú pháp query chuẩn mực như mô hình ByteByteGo:

  • Phân trang: ?limit=10&cursor=0199f... (Ép kiểu @Type tránh lỗi 400).
  • Sắp xếp: ?sort=created_at:desc,email:asc.
  • Bộ lọc nâng cao: ?created_at=gte:2026-01-01,lt:2026-02-01.
  • Tìm kiếm: ?search=quantum (hỗ trợ alias ?q=...).
Phần VI • Kiến Trúc Adapter

Kỹ Thuật Adapter: Bảo Toàn 100% Service & Schema

Làm sao nâng cấp toàn diện API v2 khi có ràng buộc "Tuyệt đối không đụng vào Service và Schema"?

Mô Hình Adapter Hai Chiều (Bi-directional Adapter)
[ HTTP Client v2 ]
      │ (Gửi query 'search', payload v2, Accept: application/problem+json)
      ▼
[ Controller v2 & DTO v2 Adapter ]
      │ ──► Map: dto.toLegacyQuery() { q: dto.search ?? dto.q }
      ▼
[ Frozen Service Layer (AuthService, ChatSessionsService...) ]
      │ (100% Code nguyên bản, không sửa 1 dòng)
      ▼
[ Response Serializer / RFC 9457 Filter ]
      │ ──► Format: Chuẩn hóa envelope, gắn _links HATEOAS v2
      ▼
[ HTTP Response v2 ]
Các Giá Trị Adapter Đạt Được
  • Không Xâm Lấn Domain Core: Mọi logic nghiệp vụ, transaction và cache phức tạp của Service được bảo toàn nguyên vẹn.
  • Ép Kiểu Dữ Liệu An Toàn: Ép kiểu chuỗi URL thành number nguyên thủy thông qua class-transformer, xóa bỏ hoàn toàn lỗi "FE truyền limit bị 400".
  • Bảo Mật Chống Mass Assignment: ValidationPipe với whitelist: true tự động tước bỏ mọi trường lạ người dùng cố tình gửi lên.
  • HATEOAS v2 Tự Động: LinksInterceptor tự động gắn các siêu liên kết điều hướng _links (self, next, session, messages...) trỏ đúng vào v2.
